# Stage 2 声学管线：冲突分析与修订方案

日期：2026-09-19。**2026-09-22 用户确认修订建议并授权实施。** 下文保留审查时的方案与阶段划分；实际实现、测试及剩余限制见 [服务器原音实现说明](STAGE_TWO_SERVER_REFERENCE.md)。

本文审查用户提供的 Phase 1 acoustic analysis pipeline 要求，并提出兼容当前 Libitu 的修订版本。讨论范围包含服务器处理、参考原音上传和持久任务；2026-09-19 审查轮仅整理分析和方案，未修改业务代码、依赖声明或数据库，也未部署服务。此前“先做离线管线”的选择曾被“仅分析”要求替代；随后 2026-09-22 用户明确确认执行，实施范围按修订后的 A–D 推进。

## 1. 结论

服务器预处理、私有音频资产、持久任务、逐句结果可复用，符合文件式原音的目标方向。但附件不能原样实现：它混用了字幕定位和声学证据，存在时间轴计算错误，并将尚未验证的启发式算法当作语音现象检测和评分。其 BackgroundTasks 流程也不满足持久任务要求。

建议首期交付“可恢复的参考音频分析基础”：获取允许处理的所选片段，保存私有资产，执行规范化、对齐及物理量测量，持久化逐句结果。保留 Sounds、Rhythm、Melody 三层，但只展示有证据支持的内容；八类现象识别和用户发音评分单独验收。

“LLM 做规则推断，不做声学分析”继续成立。规则推断本身也不是几乎确定的实际发音判断：flap、弱读等还受重音、语速、方言和韵律环境影响。没有独立评测，不接受“95% 以上准确率”的承诺。现有词典和规则可以继续工作，首期无需为了规则候选新增付费 LLM 调用。

## 2. 当前实现边界

以下按当前仓库代码和最近的实现文档核对，不能沿用较早的“全部仅在浏览器保存”描述。

## 3. 与现有架构和原要求的冲突

| 原要求 | 冲突或缺陷 | 修订建议（待确认） |
|---|---|---|
| 新建 `backend/`，另写 JWT 和 Supabase 接入 | 重复现有 API、鉴权及数据边界 | 放入 `apps/api/app`，复用已验证的 Clerk identity、repository 和配置模式；无需为附件目录结构新建服务根目录 |
| 客户端上传任意 `user_id`、句子和片段标识 | 可与账号所有权、服务端蓝图冲突；现有 segment ID 也不能直接假定为 UUID | owner 来自已验证身份；服务端解析既有内容/片段/句子标识、文本和版本；客户端时间戳只作经核验的提示 |
| 每词裁剪后循环 MFA，同一语料目录不断积累文件 | 丢失上下文、重复处理；输入输出混用 | 完整句子或连续语段对齐，必要时批量语料处理；输入、输出和工作目录隔离 |
| 对齐结果再次减去 `segment_start_ms` | 裁剪起点已是片段相对时间，非零视频起点会产生负时间 | 只在视频→片段时减一次；裁剪→片段只加实际裁剪起点 |
| 调用者 ±80ms，trim 又 ±200ms | 重复补边、偏移计算与实际文件不符 | 补边统一在一处，返回实际采样帧边界；分开记录分析上下文和播放范围 |
| MFA 失败则均分音素区间 | 把人工插值当声学证据 | 返回 `unavailable` / `failed`；字幕定位可继续显示，但不能冒充 MFA 对齐 |
| 假定 `english_mfa` 为 CMU ARPAbet | 模型、词典的音素集不一定相同 | 显式记录模型/词典版本与哈希，保留原音素集；映射到 IPA 需要独立且经过核验的映射 |
| gap 很小即连读，短闭塞即 flap | 线索不等于现象实现；强制对齐也不能证明音素确实发出 | 先输出测量，检测器验证后才输出 observation；不据此改写 `actual_ipa` |
| 固定 F1/F2 即 schwa，固定 dB 即 h-drop | 未处理说话人差异、增益、噪声与无效帧 | 测量附有效帧与质量状态；归一化和判定阈值必须实测 |
| 元音 <100ms 判断发音错误 | 忽略语速、重音、元音种类和上下文 | 首期只输出时长，不输出错误或扣分 |
| 手写公式作为 `confidence` | 未校准；linking 公式甚至可超过 1 | 不把启发式分值命名为概率；正式置信度需校准与评测出处，缺证据则弃权 |
| prominence 最大词就是核重音 | 声学显著性不等于核重音，短句 z-score 还可能零方差 | 首期可输出各物理量，不生成确定的句重音/核重音结论 |
| 依据 JSON3 间隔重新断句 | 字幕间隔不是静音；破坏已保存练习和句子 ID | 复用既有句子；声学停顿和语调单位另建子级信息，不重切练习句子 |
| 单个 `right_boundary` 表示现象 | 一个位置可能多现象，词内现象不属于下一词边界 | 使用观察数组，明确 word/phone/boundary 目标及各自证据 |
| “八项完整实现”，同时 `/compare` 为 stub | `final_voicing` 未给算法，完整实现和占位接口自相矛盾 | 缩小首期承诺；未实现比较接口不返回假成功，也不承诺八项已验证 |
| `video_id:start` 缓存 | 忽略音频、终点、字幕版本、模型与所有权 | 用授权范围、资产哈希、文本/句子版本、模型/配置版本确定分析身份 |
| 七天缓存内保存一小时签名 URL | 返回结果可能已无法播放 | 保存对象标识，读取时鉴权并重新签名，或复用鉴权音频代理 |
| 任意 tab-capture 音频上传及跨用户共享 | 用户录音留存选择不授予第三方原音处理和共享权利 | 原音单独验证来源能力及使用范围；默认私有，允许共享的授权资产才进入共享缓存 |
| BackgroundTasks + Realtime 即后台任务 | 无持久状态、崩溃恢复或可靠领取；知道 segment UUID 不等于有访问权 | 数据库任务状态 + 独立 worker + 租约/重试；先提交结果再通知，重连查询补齐 |
| 每句重复 CREPE/VAD，缺依赖静默切换 | 重复计算、算法版本不明确，CREPE 另带 TensorFlow | 片段级可复用特征只算一次；采用显式配置的算法，缺依赖明确失败或降级 |
| 假定本机 Python 3.11、MFA 和模型已就绪 | 当前 API 环境是 Python 3.13，未核实的固定路径不能当部署事实 | 分离声学 worker 运行环境，锁定兼容版本与模型；先验证可运行性 |
| 七个 mock 测试即算法验收 | 只能证明分支行为，无法证明真实语音识别准确率 | 协议测试、真实模型执行、人工标注评测分别报告 |

## 4. 修订后的数据流

```text
进入内容 → 核验来源能力/已有资产
确认练习片段 → 复用已有文件，或获取允许处理的片段
             → 私有上传暂存 → 校验/完成资产登记
             → 创建持久分析任务 → 独立声学 worker
             → 规范化 → 质量检查 → 对齐 + VAD/F0/能量/时长等测量
             → 逐句保存版本化结果 → 事件通知 + 查询恢复
             → 前端逐句读取 Sounds / Rhythm / Melody
```

输入已经是服务器可读的授权文件时，不必经浏览器重新上传。浏览器上传只是输入适配器之一，不能作为所有来源的唯一获取路径。

JSON3 是文本、句子导航和词定位提示，不是声学检测结果。已有可靠转写时无需先跑 Whisper；对齐失败时也不应自动用新转写覆盖既有练习文本。以后引入 ASR 做内容核对，需要独立契约和误识别处理。

普通 YouTube 页面不自动获得文件分析资格。不具备允许获取和处理的原音来源时，保留当前可用练习能力，明确原音服务器分析不可用。这是延续仓库已接受的来源边界；本文不新增法律结论。

文件源可用后，准备动作可在用户确认片段后自动启动，显示总体和逐句状态，优先当前句/下一句。无需每句重新授权，也不要求为采集而完整 1× 播放。文件获取能力尚未落地前，仅增加服务器处理不能消除现有 Chrome tab-capture 的启用步骤。

## 5. 时间轴和证据契约

### 三种时间必须显式区分

- 视频绝对时间：保留 JSON3 的毫秒时间，标明 provider 来源及估计词尾。
- 片段相对时间：规范化音频的第一个采样点为零，内部统一用秒。
- 裁剪相对时间：MFA 等裁剪输出的零点，以实际裁剪帧起点换回片段时间。

例如视频片段从 120 秒开始，句子从视频 123 秒开始；实际裁剪从片段 2.8 秒开始。MFA 给出的音素起点为裁剪内 0.25 秒，则片段时间为 3.05 秒，视频时间为 123.05 秒，不能再减去 120 秒。

输入若来自连续 1× 缓冲，校验完整覆盖范围。拼接、跳转或变速采集不能只给一个 `segment_start_ms` 就假定映射成立；不满足映射条件则不能进入此简化输入契约。

### 分开存四类信息

1. `rule_candidates`：词典和规则推断的可能现象，包含条件及来源。
2. `alignment`：词/音素定位、算法版本、匹配状态；失败没有假时间。
3. `measurements`：F0、能量、时长、停顿、有效帧及单位，不附伪造检测概率。
4. `observations`：经验证检测器对某一目标的判断，包含证据和弃权原因；首期允许没有任何已验证观察。

F0 缺失用有效性掩码/空值表达，不把零 Hz 当有效频率，不跨无声区补出曲线。强制对齐仅把给定文本定位到音频，并不证明实际说了正确文本；内容核对、音质和定位质量应分开记录，未核对明确 `not_checked`。

分析结果关联稳定的 `sentence_id`、输入版本和分析版本。原音观测与用户观测分开保存。两者后续只有在内容、定位和质量满足比较条件时才参与比较；未知不等于未发生，也不等于用户读错。

## 6. 服务器、存储与任务设计

下面为逻辑设计，表名和路由名尚未定稿，实施前须与现有 schema 逐项映射。

| 对象 | 需要保存的核心信息 |
|---|---|
| 参考资产 | 来源记录、处理/共享范围、owner 或受控共享范围、片段边界、对象路径、音频哈希、解码后时长、状态、保留策略 |
| 分析任务 | 输入资产、文本/句子快照版本、分析版本、幂等键、状态、尝试次数、租约/心跳、下次重试时间、错误码、取消/删除标记 |
| 逐句结果 | 句子 ID、资产与任务版本、对齐状态、各项测量及质量状态、完成时间；较大轨迹可保存私有对象引用 |
| 用户分析关联 | 现有 attempt ID、用户音频资产、用途/留存选择、原音版本及分析版本；不另建重复的练习历史体系 |

建议上传和分析分离：先登记上传意图并获得资产 ID，上传后服务端验证大小、哈希、容器、实际解码时长和来源映射，完成资产登记后才允许创建任务。服务器已有文件直接复用资产。未完成上传不能显示为“分析中”，失败重试不应反复上传同一资产。

建议接口能力：创建/完成参考资产、创建分析任务（返回 202 与 job ID）、查询任务与逐句结果、读取授权音频、取消任务、删除资产及其派生结果。身份来自现有 FastAPI 鉴权；任务 ID、视频 ID 或对象路径都不能替代权限验证。浏览器不能选择任意 owner 或存储路径。

任务状态建议使用 `queued / processing / completed / partially_completed / failed / cancelled`，另有逐句状态供处理中渐进展示。worker 原子领取并维护租约，超时后可恢复；可重试错误与输入错误分开，次数有上限。逐句结果按不可变输入身份幂等写入，重复消费不产生重复记录。模型/文本变化产生新版本，不覆盖原结果解释。

复用现有队列基础设施，但数据库是任务和结果的事实来源。增加定期扫描以找回“数据库已入队、消息未送达”的任务，避免数据库和消息队列双写遗漏。只有结果提交成功后才通知前端；通知丢失时通过鉴权查询恢复。优先复用现有事件机制，Supabase Realtime 并非首期必需依赖；若采用，必须使用已验证的私有订阅权限。

删除/取消必须胜过迟到的 worker：最终提交前检查状态和输入版本；已删除资产不得被重试重新创建。定期清理未完成上传、孤立对象、过期临时文件及失效任务租约。数据库备份、账号注销和长期留存清理不能仅靠删除单条业务记录来承诺。

签名 URL 不进入长寿命结果缓存，按需鉴权签发；用户历史音频可继续使用现有鉴权代理。缓存命中需同时满足输入身份、分析版本和访问范围，不能凭相同 YouTube ID 跨用户复用私人原音。

## 7. 声学首期范围

建议使用 FFmpeg 统一解码和采样规格；MFA 处理词/音素定位；Silero 处理语音活动；Parselmouth 提供明确版本的 F0/能量/候选共振峰测量。准确的安装包名为 `praat-parselmouth`，不是根据导入名随意安装。CREPE 可作为后续 A/B 候选，不在首期同时强制引入两套 F0 依赖，也不静默切换算法。

当前浏览器的 Pitchy/Silero 与服务器版本不同，轨迹和阈值不保证等价。服务器结果必须携带版本；在没有对照测试前不能无提示替换原有结果或把旧分数解释成新算法输出。

| 类别 | 首期可以提供 | 暂不承诺 |
|---|---|---|
| Sounds | canonical 读音、规则候选、对齐区间和局部测量 | 八项现象的可靠发生/未发生、完整 actual IPA、发音扣分 |
| Rhythm | VAD 区间、停顿、词/音素时长、能量变化 | 未校准重音级别、核重音及语言水平结论 |
| Melody | 有效 F0 轨迹、覆盖率与缺失区域 | 仅凭轮廓相似度给出正确性评分 |

八类检测器中，连读需要超出 gap 的证据，flap 需要排除其他短时实现，弱读和 h-drop 需要质量与上下文约束，元音长度和 final voicing 需要条件基线，elision/assimilation 不能只靠规则候选认定发生。逐类获得人工金标、独立评测和弃权标准后再发布，不统一套用 0.55/0.75 阈值。

`/compare` 不以 stub 作为完成项。此轮拟议首期只准备参考分析基础；用户录音服务器分析与原音比较作为下一独立验收项，复用已有 attempt 体系。若要求它与参考管线同时上线，需明确扩大首期范围及评测工作，而非增加空接口。

## 8. 建议实施顺序与验收

以下为当时提交确认的分阶段计划；2026-09-22 的实际交付状态以服务器原音实现说明为准。

| 顺序 | 交付内容 | 必须验证 |
|---|---|---|
| A. 契约与运行环境 | 来源能力、时间轴、结果 schema、独立声学 worker 环境和固定模型 | 非零视频起点、补边映射、模型/词典兼容、依赖可运行性 |
| B. 离线分析内核 | 规范化、质量检查、完整语段 MFA、VAD/F0/能量/时长 | 真实文件和真实 MFA 执行，重复词/未知词、无声/噪声、超时、坏音频、部分失败 |
| C. 原音资产与持久任务 | 私有资产、上传完成校验、任务表/worker、结果存储和恢复 | 越权拒绝、幂等重试、进程重启、过期租约、消息遗漏、删除与迟到结果竞态 |
| D. 前端接入 | 所选片段自动准备、逐句读取、加载/失败/重试、刷新恢复 | 切句和切账号不会串结果，已有三层及练习历史不回退；有文件来源时不逐句启用捕获 |
| E. 检测与用户比较 | 人工标注、独立测试集、逐类检测、用户侧对齐和比较 | 各类准确率/召回率、覆盖率与弃权率，以及差音质和文本不符情况 |

A–D 为建议的修订首期，涵盖用户提到的服务器处理、原音上传和持久任务；B 是内核验证步骤，不是将整个目标缩减成离线 CLI。D 的无捕获授权体验依赖 F1–F3 的允许文件来源，不能跳过来源可行性。E 对应后续更深入的 M4b/F4–F5 能力，单独验收。

测试证据必须分开报告：合成信号验证物理量和时间轴，mock 验证协议分支，真实文件验证实际工具链，人工标注验证语音检测质量。当前 16 条 dev 音频和待标注目标不足以声明通用检测准确率，也不能作为同时调参和报告正式准确率的唯一数据集。

## 9. 待确认问题及建议默认值

| 问题 | 建议默认值 | 对范围的影响 |
|---|---|---|
| 首期什么原音可以进服务器？ | 自有/明确许可文件及已登记允许处理的来源；普通 YouTube URL 不自动转换为文件权限 | 没有允许的文件来源，就不能承诺去掉现有采集操作 |
| 首期完成到哪一层？ | A–D：参考原音服务器处理全链路；E 独立评测后交付 | 保留服务器目标，同时避免假检测、假评分 |
| worker 在哪里运行？ | 独立长驻 CPU worker，模型预装，API 保持轻量；用真实片段测吞吐后决定是否需要 GPU | 具体云厂商、机器规格和延迟目标待基准数据决定 |
| 音频保存多久？ | 原音按来源授权范围和产品保留策略；用户已有录音选择保持不变 | 参考资产 TTL、临时分析音频 TTL、账号删除清理必须另行落定，不能由任务缓存 TTL 代替 |
| 是否共享参考分析？ | 初期按账号/授权范围私有；明确可共享的资产才启用共享 | 提高后期缓存命中不应牺牲权限边界 |
| 是否新增外部 API key？ | 声学模型本地运行，不需要 Whisper/DeepSeek/CREPE 商业 API key；复用现有服务端鉴权/存储配置 | 部署机器、模型下载和存储仍有成本；采用新供应商时再配置凭据 |

参考原音留存、用户录音长期保存、临时云端分析以及模型训练是不同用途。现有“保存录音”选择不能被悄悄扩展为全部用途；具体交互在对应阶段确定，模型训练和人工审听继续默认关闭。
