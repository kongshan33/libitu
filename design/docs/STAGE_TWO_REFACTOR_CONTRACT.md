## Deterministic word check: word-match-v1

Normalize both source and independently recognized text with Unicode NFKC, lowercase and curly-to-straight apostrophe conversion, then extract `[a-z0-9]+(?:'[a-z0-9]+)*` tokens. Punctuation is not a token; `don't` is one token. Hyphenated words split. Do not expand contractions, infer synonyms, rewrite numbers or supply the expected sentence as an ASR prompt. Retain original display strings and source character spans. Bound each sequence to 1,024 tokens; larger inputs return word_check_limit_exceeded with no tier or expensive analysis.

Use sequence edit-distance alignment: exact match cost 0, substitution/deletion/insertion cost 1. Among minimum-cost paths maximize exact matches; resolve remaining ties by diagonal, source deletion, recognized insertion during deterministic backtracking from the end. Emit source and recognized indices so repeated words never rely on text lookup. Version the algorithm; golden repeated-word fixtures must fix its tie behavior before runtime adoption.

Each source token is `matched`, `substituted` or `omitted`. Each recognized token belongs to a matched/substituted pair or an `inserted` operation. Insertions carry a source boundary index in 0..source_count (0 before the first word); multiple insertions retain recognized order.

Match rate is matched_count / source_count. Insertions are displayed but do not change the denominator in v1. Gate with integer arithmetic, not the rounded display percentage:

| Tier | Exact test | Requested analysis scope |
| --- | --- | --- |
| below_60 | matched_count * 100 < source_count * 60 | none |
| partial_60_85 | >=60% and <85% | sound_only |
| full_85_plus | matched_count * 100 >= source_count * 85 | all_layers |

Zero source tokens, unreliable/empty ASR, or invalid audio produce an unavailable/uncertain check, null tier and no analysis; never label uncertainty as 0% or a definite omission. Display percentage may be rounded but cannot determine eligibility. 85%+ is not `all words matched`; reserve that message for every source word matching and no extra words.

## Execution and evidence

Decode and perform inexpensive input validity checks first, then ASR and word matching. Persist/read the word check immediately. Do not run MFA or full VAD/F0 extraction below 60%. Uncertain checks terminate as needs_review without further analysis.

For 60–<85%, run only the alignment/measurements necessary for available Sound evidence; do not run Rhythm/Melody assessment or F0 solely for those layers. Sound-only is not just hiding a completed all-layer result. If no supported Sound target can be measured, return an explicit unavailable result without inventing detectors.

For >=85%, start the existing available three-layer measurement pipeline. Align the recognized words rather than forcing omitted/substituted expected words into the learner audio. Map exact matched positions back to the source axis; unmapped positions remain gaps. A linking/boundary target requires all participating words to be matched, adjacent and reliably timed; an inserted word breaks that boundary. Failed alignment or audio quality withholds affected evidence without changing the original match tier. Full-scope results may therefore be partial/unavailable.

Only after a reliable check selects a non-none scope may analysis wait for its captured reference. Keep that take's immutable reference binding; new preparation cannot substitute a different reference for a historical take. Reference revocation/deletion and stale worker completions retain current fence/access checks. A failed/absent reference permits clearly labelled learner-only measurements, never a fabricated paired comparison. Do not rerun successful word checks when retrying a downstream stage.

Existing server-analysis opt-in remains required for uploads/checking. With consent off, recording/replay/practice persistence remain available; show analysis not requested, not a failed match. Stopping recording does not guarantee immediate network results or a simulated checking duration.

Three completed same-input runs used 3.746 s / nine-word synthetic speech, browser WAV reference upload (119,958 bytes), Opus learner upload (35,683 bytes), real FastAPI routes, hosted Supabase objects/queue, one actual Reference worker and one learner worker, and the existing practice polling hook/layer components in a temporary test page. | Run | Reference registration start → final visible comparison | Reference audio PUT start → visible Ready | Learner audio PUT start → visible comparison |
|---|---:|---:|---:|
| 1 | 50.746 s | 33.800 s | 37.342 s |
| 2 (Reference save error/retry) | 80.131 s | 74.560 s | 71.490 s |

Reference MFA took 17.776–34.336 s per invocation (plus a 23.250 s repeated invocation in run 2); learner MFA took 17.012–24.364 s. Learner ASR took 5.404–11.442 s. VAD/F0 extraction took 0.343–0.881 s per audio; final comparison took 0.002–0.007 s. Local audio cache reads took approximately 1–4 ms; no worker audio cloud download occurred. Upload endpoint response time was 3.168–4.315 s for Reference and 3.653–4.334 s for learner; these include storage and serial validation/registration reads, not only byte transfer. Actual storage POST took 1.492–2.030 s and 1.064–1.313 s respectively. Final learner save acknowledgement → UI was 1.161–2.961 s; status GETs took 0.755–1.551 s with the regular 2.5 s delay after each response.

MFA processes overlapped in all runs (9.296 s in run 1), proving parallel execution. No old serial end-to-end control was measured, so no overall speedup percentage is claimed. Same-input run 3 varied substantially; CPU/IO attribution was not measured, so do not treat three runs as a stable latency distribution.

Run 2 exposed an avoidable long-tail path: Reference acoustic calculation completed at +26.081 s; the result-write call took 5.011 s and entered the HTTPError retry path. Next claim came 18.004 s after retry acknowledgement, followed by 23.250 s of repeated MFA. Trace did not capture the exact exception class/status, so this establishes a failed storage request, not a specific timeout cause. The learner saved its own acoustic checkpoint at +36.821 s and correctly resumed without re-reading audio or repeating ASR/MFA.

Proposed next optimizations (not implemented by this measurement):
1. Retain computed Reference payload and boundedly retry the same fenced save on transient errors, preserving lease/expiry/cancel/delete checks, before falling back to whole-job retry.
2. Prototype a resident isolated MFA aligner with the existing pinned model/parameters; verify identical alignment and quality behavior before rollout. Current CLI still reconstructs model, lexicon objects and aligner per audio.
3. Reduce serial database round trips in registration/upload/status; reuse already-validated attempt data or a scoped RPC while preserving owner/source-revocation checks. See [Supabase database functions](https://supabase.com/docs/guides/database/functions).
4. Wake checkpoint-complete learner work when Reference finishes instead of fixed 15 s availability delay; improve terminal-result notification. This fixed wait was not the main delay in runs 1/3 or the dominant added delay in run 2.
5. Supervise services independently: after all three measurements, the unrelated blueprint worker suffered an Upstash TLS ConnectTimeout and caused pnpm's entire dev group to exit. This did not affect the measured runs, but can otherwise interrupt acoustic work. Normal services were restarted.
